- # Modbus RTU протокол ONI A650

Источник: Приложение А руководства ONI A650 (издание 1). Разделы: А.2 (параметры канала), А.3 (формат протокола/CRC), А.4 (размещение регистров, коды команд), А.8 (примеры кадров).

> Статус: частично подтверждено. Всё, что помечено `TODO`/`hypothesis`/`discrepancy`, требует проверки на реальном устройстве перед использованием в коде записи.

## 1. Физический уровень

- Интерфейс: **RS‑485**, асинхронный, полудуплекс, топология «один ведущий — много ведомых».
- Рекомендуемый кабель: **экранированная витая пара**; экран заземлять со стороны привода.
- Цифровые сигнальные кабели — по возможности **не более 20 м**; не прокладывать вместе с силовыми (перекрёстные помехи).
- Терминальный резистор 120 Ом включается перемычкой/переключателем RS485 на клеммнике (см. `docs/WIRING.md`).

## 2. Параметры канала (настраиваются параметрами F15)

| Параметр | Имя | Значения | По умолчанию |
|---|---|---|---|
| F15.00 | Скорость передачи | 0:4800, 1:9600, 2:19200, 3:38400, 4:57600, 5:115200 бод | **1 (9600)** |
| F15.01 | Формат данных | 0:1‑8‑N‑2, 1:1‑8‑E‑1, 2:1‑8‑O‑1, 3:1‑8‑N‑1 | **0** |
| F15.02 | Локальный адрес | 1÷247 (0 — широковещательный) | **1** |
| F15.03 | Коммуникационный тайм‑аут | 0.0÷60.0 с | 0.0 |
| F15.04 | Задержка ответа | 0÷200 мс | 1 |
| F15.05 | Режим «ведущий‑ведомый» | 0: ПЧ «ведомый», … | 0 |

### ⚠ Discrepancy по формату данных (критично)
- Раздел **А.2** утверждает: формат по умолчанию терминала RS485 = **1‑8‑N‑1**, скорость 9600.
- Параметр **F15.01** со значением по умолчанию **0** описан как **1‑8‑N‑2** для RTU.

Эти два утверждения несовместимы. **ПО не должно полагаться на «значение по умолчанию»** — формат данных обязан задаваться явно и проверяться на приборе. По умолчанию в конфигураторе предлагаем `1‑8‑N‑1` (как в А.2), но с обязательной возможностью переключения и предупреждением.

### ⚠ Discrepancy по адресу ведомого
- `F15.02`: адреса 1÷247.
- Таблицы запросов А.4: «Адрес ведомого 1, диапазон **0÷127**».

Возможно, RTU‑кадр принимает только 0÷127, несмотря на диапазон параметра. Проверить на приборе; в коде валидировать оба предела и предупреждать при >127.

## 3. Формат кадра RTU (А.3)

```
[ тишина ≥ 3.5 символа ][ адрес 1 ][ функция 1 ][ данные N ][ CRC16 2 ][ тишина ≥ 3.5 символа ]
```

- CRC считается по адрес+функция+данные; **стартовый/стоповый бити в расчёт не входят** (А.3, п.2).
- CRC передаётся **младшим байтом вперёд** («переключается с младших байтов на старшие», А.3).
- Межфрейзовая тишина — стандартные T1‑T2‑T3‑T4 (3.5 символа); точные численные значения в фрагменте не раскрыты → делать настраиваемым.

## 4. Алгоритм CRC‑16 (А.3, подтверждено)

Полином **0xA001** (обратный 0x8005), инициализация 0xFFFF, бит‑реверс на входе/выходе — это канонический **CRC‑16/MODBUS**. Описание в А.3 (XOR байта с регистром CRC, 8 сдвигов, XOR с `A001H` при младшем бите = 1) соответствует ему. Ручная верификация: CRC запроса `01 03 30 00 00 01` = `8B 0A` — сходится.

## 5. Поддерживаемые коды команд

### 0x03 — чтение параметров / состояния
Запрос: `адрес(1) | 0x03 | стартовый адрес регистра(2) | количество регистров(2) | CRC(2)`.
Ответ: `адрес(1) | 0x03 | количество байт(1) | данные(2×N) | CRC(2)`.

> **Ограничение из руководства (А.4):** «Последовательно считывается **максимум восемь** кодов функции». То есть за один запрос 0x03 нельзя читать длинный блок — код обязан резать чтение на чанки ≤ 8 регистров. Это нестандартно узко и важно для генерации кода.

### 0x06 — запись одного кода функции / параметра управления
Запрос: `адрес(1) | 0x06 | адрес регистра(2) | значение(2) | CRC(2)`.
Ответ: **эхо** запроса (подтверждено А.8.2–А.8.4: «Принимаемые данные» идентичны «Данным для посылки»).

### 0x08 — диагностика схемы и настройка
Запрос: `адрес(1) | 0x08 | стартовый адрес регистра(2) | номер регистра(2) | CRC(2)`.
Содержание подфункций/данных в фрагменте не раскрыто → `TODO`.

### Ошибки (exception)
Стандарт Modbus: в ответе функция = `(исходная | 0x80)`, далее код исключения. Типичные коды: `0x01` illegal function, `0x02` illegal data address, `0x03` illegal data value, `0x04` operation failed.  
> ⚠ Явной таблицы исключений в присланном фрагменте **нет**; коды выше — обще­модбусные. Поведение прибора (в т.ч. предполагаемый код для «запись в read‑only») проверить захватом реального ответа. Не зашивать в код как факт.

## 6. Размещение адресных регистров (А.4.3) — ключевая находка

Старший байт адреса = индекс группы, младший = номер параметра в группе.

| Группа | Старший байт ОЗУ | Старший байт EEPROM (СППЗУ) |
|---|---|---|
| F00 | 0x00 | 0x80 |
| F01 | 0x01 | 0x81 |
| F02 | 0x02 | 0x82 |
| … | … | … |
| F30 | 0x1E | 0x9E |
| F31 | 0x1F | 0x9F |
| U00 (только чтение) | 0x30 | — |
| U01 (только чтение) | 0x31 | — |

Отсюда **формула адреса параметра в ОЗУ**: `addr = (group_index << 8) | param_index`.  
Примеры: `F00.00 → 0x0000`, `F01.08 → 0x0108`, `F13.01 → 0x1301`, `F15.02 → 0x1502`, `U00.00 → 0x3000`, `U01.00 → 0x3100`.  
EEPROM‑зеркало для F‑групп: `0x80 | group_index` в старшем байте (например `F15.02 → 0x9502`).

> ⚠ **Hypothesis:** в присланном фрагменте **нет ни одного примера** Modbus‑обмена с параметром `Fxx.yy` (все примеры А.8 — это банк управления 0x20xx). Поэтому связка «параметр ↔ адрес ОЗУ по формуле выше» пока **не подтверждена обменом** и должна быть проверена: прочитать `0x1502` (ожидаем локальный адрес = 1) и `0x3000` (ожидаем рабочую частоту) и сверить с пультом. До подтверждения код записи параметров обязан работать в режиме «только по явно подтверждённым адресам».

## 9. Масштабирование

- Частота (0x2001, 0x3000, U00.00/U00.01): **0.01 Гц** (3000 = 30.00, 5000 = 50.00). Подтверждено А.8.2.
- Прочие параметры (проценты, токи, времена, ПИД‑коэффициенты): масштаб в фрагменте **не задан** однозначно → в `parameters.csv` поле `scale` = `unknown`, заполнять по прибору. Не применять 0.01 «ко всему».

## 10. Тайминги

- Межфрейзовая тишина: стандарт Modbus RTU 3.5 символа; делать настраиваемой (в фрагменте чисел нет).
- Учитывать `F15.04` (задержка ответа) и `F15.03` (тайм‑аут) при выборе таймаутов клиента.

## 11. Broadcast

`F15.02 = 0` — широковещательный адрес. Для **записи/пусков не использовать** без отдельного продуманного сценария (см. `docs/SAFETY.md`).
