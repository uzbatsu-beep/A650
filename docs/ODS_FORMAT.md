# Формат OniDriveStudio .ods

Исследование от 2026-11-15. Объект: предоставленный EXE с VERSIONINFO 1.2.7.0,
SHA-256 `ffac6008567c2403544ab0ca52f895da431e74684b25cba9f84835ffa0969097`.
Формат восстановлен по процедурам сохранения и загрузки, без запуска EXE.
Настоящий сохранённый файл `.ods` пока не предоставлен; полная совместимость
с программой производителя не заявляется.

## Установленная структура

Это текстовый формат INI/Preferences, не ZIP OpenDocument Spreadsheet.
Писатель использует кодовую страницу 65001 (UTF-8), текстовые группы,
ключи и значения; в библиотеке присутствуют UTF-8 BOM, скобки `[ ]`,
разделитель ` = `, CRLF и комментарии `; `. Наличие BOM в конкретном
экспорте нужно проверить образцом. Расширение совпадает с табличным ODS,
но для открытия этого файла не требуется LibreOffice.

Схематический пример ниже **составлен нами по коду**, не является экспортом
OniDriveStudio и не предназначен для загрузки в реальный привод:

```ini
; Файл конфигурации ONI Drive Studio
[General]
Model = ПЧ ONI A650
Address = 1
Port = COM3
Baud = 3
Parity = 0
DataBit = 1
StopBit = 1
Mode = 1

[Parameter Set]
F13.01 = 500

[Parameter Read]
F13.01 = 450

[Check Parameter]
F13.01 = 1
```

| Секция | Смысл по процедурам EXE |
|---|---|
| General | Модель оборудования и сохранённые настройки элементов подключения |
| Parameter Set | Числовые заданные значения, ключ — код параметра |
| Parameter Read | Числовые прочитанные значения, ключ — код параметра |
| Check Parameter | Отмеченные строки таблицы, записывается флаг 1 |

Строки модели именно `ПЧ ONI A650` и `ПЧ ONI A650M`. Загрузчик читает
Model, проверяет модель и вызывает соответствующее создание каталога.
Имена, описания, адреса RAM/EEPROM и диапазоны берутся из встроенных
процедур, а не из сохранённого `.ods`.

`Baud`, `Parity`, `DataBit`, `StopBit`, `Mode` сохраняются как состояния
GUI-контролов. Например, загрузчик применяет целочисленное значение `Baud`
к контролу с ID 0x87; считать `Baud=3` скоростью 3 бод нельзя.
Полное соответствие индексов реальным настройкам пока не проверено.
`Address`/`Port` сохраняются строками соответствующих контролов.

Числовые параметры сериализуются через формат `%d` из 32-битных полей.
При загрузке они снова записываются в числовые поля параметра. В файле
нет отдельного поля масштаба или единицы измерения. Наш читатель сохраняет
целые числа без перевода в Гц/%/слова Modbus: смысл определяется каталогом
конкретной модели и путём преобразования при обмене.

При сохранении значения сравниваются со значением по умолчанию, а для
неопределённого default (`----`/пустая строка) — с нижним пределом.
Поэтому файл может быть **разреженным**: отсутствие ключа не доказывает,
что значение равно нулю, и не доказывает, что оно было прочитано с ПЧ.
Политику восстановления пропущенных значений нужно проверять на реальном
экспорте и соответствующем каталоге. Дубликат F17.28 из встроенного каталога
особенно опасен для формата, где код параметра является ключом.

## Свидетельства в дизассемблированном EXE

Адреса VA относятся только к этому бинарнику:

- `0x503313`: процедура сохранения;
- `0x503362–0x503493`: комментарии и General;
- `0x503498–0x503581`: Parameter Set, значение поля +0x1E;
- `0x503586–0x50365E`: Parameter Read, значение поля +0x1A;
- `0x503663–0x5036E6`: Check Parameter, флаги 1;
- `0x508E..–0x509420`: загрузка, Model/General/группы параметров;
- `0x555B5E`: создание файла и установка code page 65001;
- `0x555E17`: форматирование числового значения через `%d`;
- `0x556595`: запись текстовых комментариев, групп, ключей и значений.

Листинги сохранены в `/workspace/reference/a650/studio/ods-*.asm`.

## Что реализовано и как это поможет

Добавлен `a650.a650lib.studio_profile.read_studio_profile`: офлайн-чтение
UTF-8 INI с необязательным BOM, раздельными Set/Read/Check и проверкой модели.
Дубликаты, дробные/нецелые значения, DEFAULT-наследование, ZIP и неверная
модель отклоняются. Отсутствующие параметры не заполняются нулями.
Функция не подключается к порту и не применяет настройки связи.
11 новых тестов используют **синтетические** данные, составленные по
дизассемблированию. Это проверяет наш читатель, а не работу производителя.

Этого достаточно для разработки просмотра импорта и сравнения
«задано / прочитано / текущий профиль». Можно переносить резервные копии
и сравнивать их с нашим каталогом после проверки реальных файлов.
Для записи в ПЧ по импортированному файлу дополнительно необходимы:
выбор точного профиля модели, проверка неизвестных/повторяющихся кодов,
масштабов, диапазонов и возможности записи, чтение текущих значений и diff.
Экспорт с обещанием совместимости пока не реализован.

Для окончательной проверки нужен один `.ods`, сохранённый именно этой
программой, желательно с известным изменением одного некритичного параметра
в офлайн-профиле. Подключение к работающему приводу для этого не требуется.
