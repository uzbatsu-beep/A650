# План разработки конфигуратора ONI A650

Актуализирован 15 ноября 2026 года. Это основной план продолжения работ.
Выполненное и доказательства отдельно зафиксированы в
[DEVELOPMENT_STATUS.md](DEVELOPMENT_STATUS.md); поведение целевого UI — в
[INTERFACE_DESIGN.md](INTERFACE_DESIGN.md). Исторические отчёты исследований
не заменяют актуальный статус. Дополнительные идеи из загруженных SRS/SAD
сохранены ниже, но не означают принятия всего их объёма в ближайший релиз.

## Принятые решения

- Windows, русский интерфейс, Python + PySide6, USB–RS-485 / Modbus RTU;
  разработка на симуляторе до появления стенда.
- Главный пользовательский сценарий — настройка и сравнение параметров.
  Редактирование в таблице, детали справа. Enum — список именованных
  значений с отдельным числовым кодом; числовое поле не заменяет enum.
- Раздельные профили A650/A650M, происхождение полей и явные конфликты.
  Неизвестные адреса/масштабы/доступы не становятся разрешением на запись.
- Локальное изменение проекта отделено от соединения и физического применения.
  Отсутствие ключа не означает ноль или заводское значение.
- Один активный RTU-обмен на канал, чтение A650 до 8 регистров. Поддержку
  FC16/ASCII/TCP не предполагать. Записи не повторять автоматически;
  серия FC06 не атомарна, автоматический rollback не обещается.
- Программные команды двигателя и изменение параметров — отдельные разрешения.
  Симуляция, успешные тесты и публикация preview не подтверждают работу ПЧ.

## Очередь работ с условиями завершения

### P1. Завершить интерактивный офлайн-сценарий

Редакторная часть схемы уже вынесена в отдельные [профили](EDITOR_PROFILES.md).
Raw-кодеки, signedness и условия физической записи ещё не завершены.

Уже работают 14 редакторов, файлы проекта, undo/redo, сравнение и фильтр отличий.
Осталось:

- [ ] Вынести типы, enum, единицы, precision, диапазоны, условия изменения,
  signedness, codec и provenance в версионируемую схему профиля с валидатором.
- [ ] Постепенно сверять остальные параметры по модели/редакции; отдельно
  битовые поля, десятичные разряды и зависимые диапазоны. Не включать все
  531/617 записей автоматически и не угадывать смысл type_raw/attribute_raw.
- [x] Добавить действия «убрать локальную уставку» и применение выбранного
  значения образца **в проект** с undo, не в ПЧ; явное управление источником
  сравнения и понятные сообщения ошибок.
- [ ] Довести карточку параметра и основной экран по дизайн-документу:
  показать пользовательские значения впереди технических данных; устранить
  обрезание важных полей и завершить русские подписи.
- [ ] Сохранение/открытие пользовательских проектов проверить в упакованном
  приложении, на Windows и разных DPI. Не терять изменения при закрытии,
  смене модели, ошибке сохранения, поиске и сравнении.

**Приёмка:** целый сценарий «создать → enum/число → undo → сохранить → открыть →
сравнить → принять выбранное отличие в проект» работает на Windows, неизвестные
коды и конфликты остаются явными. До этого не объявлять альфу завершённой.

### P2. Импорт OniDriveStudio

- [ ] Встроить существующий ODS-парсер в GUI с отдельным предпросмотром
  Set/Read/Check, моделью и сообщениями о неподдержанных параметрах.
- [ ] Получить настоящий ODS из OniDriveStudio; проверить кодировку,
  значения контролов, масштаб, пропуски и дубли. Не подставлять дефолты.
- [ ] Сопоставлять код с устойчивым идентификатором модели и ревизии,
  блокировать неоднозначный F17.28 и другие коллизии.
- [ ] Экспорт ODS делать только после проверки совместимости на реальных
  образцах; отчётливое различие `.a650.json` и `.ods` в интерфейсе.

**Приёмка:** реальный файл открывается без потери/подмены данных, а ограничения
совместимости подтверждены тестами на обезличенных образцах. Отсутствие образца
не блокирует P1, но не позволяет заявить совместимость.

### P3. Надёжное чтение и качество данных

В каталог добавлено ручное чтение 8 enum через симулятор, время и stale.
Осталось:

- [ ] Сверить физические кодеки параметров и модель/прошивку, лишь после этого
  разрешать чтение каталога с реального serial-порта и преобразование чисел.
- [ ] Покрыть частичные/запоздалые кадры, межкадровую паузу, переподключение,
  ограничение фоновой очереди, отмену и прогресс длительного чтения.
- [ ] Распространить timestamps/quality/stale на весь мониторинг; правильно
  обрабатывать signedness и F15.08, включая отрицательную частоту.
- [ ] Проверить, что показания старого сеанса не попадают в другой привод/
  проект; чтение не меняет локальные уставки и не выполняет запись.
- [ ] Пакетирование — только непрерывные допустимые области до 8 регистров;
  пропуски/недоступные адреса не читать без оснований.

**Приёмка:** отказные сценарии тестируются подставным портом; на стенде значения
сверяются с пультом. Ноль, отсутствие, ошибка и устаревшее значение различаются.

### P4. Контролируемое применение параметров

- [ ] Разделить разрешения параметризации и движения в GUI/CLI; проверить
  состояние и подтверждённость модели/адреса/масштаба/доступа до операции.
- [ ] Прочитать текущее → резервный снимок → diff → подтверждение → одиночная
  запись → проверка результата. RAM/EEPROM и критичные группы имеют явную
  политику; параметры связи требуют отдельного сценария переподключения.
- [ ] Вести аудит попытки и исхода, включая неизвестный результат. Обработать
  невозможность аудита до отправки. Пароли исключить из журналов и отчётов.
- [ ] Тайм-аут/повреждённый ответ после передачи: остановить очередь,
  сохранить неопределённость, не повторять и предложить проверку состояния.
- [ ] Имитировать отказы и частичное применение в симуляторе, затем проверить
  выбранные безопасные операции на изолированном стенде.

**Приёмка:** тесты доказывают блокировку недопустимых записей, отсутствие
скрытых повторов/откатов, корректный аудит и явный исход каждой операции.
Проверка на физическом приводе — отдельный обязательный результат.

### P5. Упаковка, релизы и стендовая приёмка

- [ ] Проверить актуальный workflow Windows, загрузить и выполнить .exe;
  при отсутствии доступа к Actions запросить результат, не объявлять успех.
- [ ] Проверить русский UI, DPI 100/125/150/200 %, клавиатуру, пути с кириллицей,
  запуск без администратора и поведение при отключении USB-адаптера.
- [ ] Для стенда зафиксировать модель, прошивку, интерфейс и параметры связи.
  Начать с чтения; запись и управление выполнять по отдельному протоколу
  с соблюдением [SAFETY.md](SAFETY.md).
- [ ] Релизные заметки должны перечислять поддержанные сценарии и ограничения.
  Preview не должен обещать полный конфигуратор или проверку оборудования.

**Приёмка:** проверен именно скачанный Windows-артефакт; приложен протокол
с результатами. Успешный Linux wheel/бинарник не заменяет эту проверку.

## Последующие возможности (после базовых этапов)

| Направление | Объём и зависимость |
|---|---|
| Диагностика | Err-коды с проверенной редакцией, контекст причин/параметров, история |
| Графики / Scope | Каналы, буфер, экспорт, триггеры; сначала замеры пропускной способности |
| Мастера ПИД и насосов | Проверенные сценарии/единицы, схема объекта, зависимости и подтверждения |
| Отчёты | Снимок конфигурации, изменённые параметры, источники, экспорт без секретов |
| Несколько приводов | Идентификация сеансов, очередь на канал, раздельные проекты/истории |
| Другие семейства и транспорты | Только отдельные проверенные профили; FC16/ASCII/TCP — самостоятельные задачи |
| Доступность и темы | Проверка контраста, фокуса, Narrator; темы после завершения основных сценариев |

Высокочастотный Scope, универсально «безопасные» пресеты и срок полного чтения
из приложенных документов не принимать без измерений и проверки объекта.
Переход на C++/C#/веб и поддержка всей линейки ONI не входят в ближайший релиз.

расходиться; источник каждого принятого решения должен быть сохранён.
