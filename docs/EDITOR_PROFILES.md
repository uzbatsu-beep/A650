# Профили офлайн-редакторов

Редакторы больше не описываются таблицами констант в Python. Приложение загружает
отдельный файл выбранной модели:

- `src/a650/data/editors-a650.json`;
- `src/a650/data/editors-a650m.json`.

В каждом файле явно заданы `format`, `schema_version=1`, `model`, `revision`,
`hardware_write_allowed=false` и список `parameters`. Профили независимы,
хотя текущий поддержанный набор совпадает: 8 enum и 6 числовых редакторов.
Данные взяты из предоставленного PDF с титулом A650, издание 3; наличие
профиля A650M не устанавливает совместимость с любой прошивкой A650M.

## Описание поля

Пример enum (фрагмент списка parameters):

```json
{
  "code": "F02.12",
  "kind": "enum",
  "options": [
    {"code": 0, "label": "Останов с торможением"},
    {"code": 1, "label": "Останов выбегом"}
  ],
  "source": {
    "document": "ONI_A650M_Manual.pdf",
    "title": "Руководство ONI A650, издание 3",
    "edition": 3,
    "pages": [45]
  },
  "notes": ["Описание локального редактора, не команда приводу."]
}
```

Числовой редактор: `kind=decimal`, `minimum`, `maximum`, `step` — десятичные
**строки**, `unit` — подпись единицы. Шаг текущей схемы — десятичная степень
10 с точностью не более 9 знаков после запятой, не произвольное приращение.
Диапазон должен соответствовать шагу. Это сохраняет точную арифметику Decimal.

Источник, редакция и страницы обязательны. Примечания задаются в профиле,
отображаются в карточке вместе с вариантами/диапазоном редактора. Для F15.01
отдельно сохранён конфликт источников 8E1 и заводского формата. Изменения
профиля должны повышать `revision`; существующую ревизию нельзя переопределять
другим набором значений без миграции проектов.

## Загрузка и проверка

`a650.a650lib.editor_profile` валидирует схему, модель, ревизию, уникальность
кодовых идентификаторов и enum-вариантов, типы, конечность/порядок диапазона,
положительный шаг, единицы и источники. Неизвестные типы редактора и попытка
разрешить аппаратную запись отвергаются. Полученные отображения неизменяемы,
профиль одной модели не может случайно изменить профиль другой. Данные
загружаются из ресурсов пакета и кешируются до перезапуска приложения.

GUI, валидация проекта, перенос образца и разрешённый набор чтения симулятора
пользуются профилем выбранной модели. Для физической записи эти метаданные
не используются: адреса, raw-кодеки, масштабы передачи и разрешения пока
относятся к другой, не завершённой части профиля устройства.

Чтобы добавить поддержанный редактор, нужно сначала сверить параметр и модель
по источнику, записать тип/варианты или диапазон/единицу и provenance в JSON,
повысить revision, проверить каталог и регрессионные сценарии. Поддержку нового
типа редактора (например, битового поля) всё ещё требуется реализовать в коде.
Программа не исполняет выражения или код из профиля.

## Совместимость проектов

Формат проекта остаётся `a650-offline-project`, версия 1. Старые файлы без
`editor_profile_revision` читаются по текущему профилю, значения проходят
валидацию; неизвестные целые коды enum сохраняются как раньше. Сохранение
добавляет текущую `editor_profile_revision`. Если файл явно указывает другую
ревизию, загрузчик отклоняет его до реализации проверенной миграции — значения
не переосмысливаются молча. Это не импорт/экспорт формата производителя ODS.

Проверки: повреждённые профили, отдельная валидация по модели, миграция старого
проекта, защита от неподдержанной ревизии, неизменяемость и загрузка JSON из
собранного wheel. Windows .exe отдельно собирается в Actions; успешный wheel
не является проверкой Windows или реального привода.
