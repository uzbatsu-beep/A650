# Protocol Examples — ONI A650 Modbus RTU / Примеры кадров Modbus RTU

Все примеры — ведомый `0x01`. Hex дан как последовательность байт transmission-order (CRC16/MODBUS, полином 0xA001, младший байт вперёд). Machine-readable copies: `data/frames/*.json`.

Verification legend / Легенда проверок:
- **manual** — байты взяты дословно из руководства, CRC верифицирован ✅
- **computed** — семантика из руководства, кадр восстановлен с корректным CRC (исходный EXAMPLES.md был обрезан; кадры重建 детерминированно)
- **hypothesis** — требует подтверждения на реальном приборе

## Подтверждено руководством (Приложение А.8) — использовать как golden-тесты

### 1. Уставка частоты 30.00 Гц (запись 0x06 в 0x2001) — А.8.2 — *manual* ✅
Запрос:
```text
01 06 20 01 0B B8 D4 88
```
Ответ (эхо):
```text
01 06 20 01 0B B8 D4 88
```
Разбор: адрес `0x01`, функция `0x06`, регистр `0x2001`, значение `0x0BB8` = 3000 → 30.00 Гц (масштаб 0.01), CRC `D4 88`.

### 2. Пуск вперёд (запись 0x06 в 0x2000 = 0x0001) — А.8.3 — *manual* ✅
Запрос / ответ (эхо):
```text
01 06 20 00 00 01 43 CA
```

### 3. Останов с замедлением (запись 0x06 в 0x2000 = 0x0005) — А.8.4 — *manual* ✅
Запрос / ответ (эхо):
```text
01 06 20 00 00 05 42 09
```

## Частично подтверждено — запрос валиден, ответ требует захвата с прибора

### 4. Чтение рабочей частоты U00.00 (0x03, регистр 0x3000) — А.4.3
Запрос (CRC верифицирован вручную = `8B 0A`; адрес согласуется с А.4.3; регистр передаётся как число, без смещения bank):
```text
01 03 30 00 00 01 8B 0A
```
Ожидаемый ответ (формат FC 0x03; **значение и CRC НЕ подтверждены фрагментом руководства — захватить с прибора**):
```text
01 03 02 <hi> <lo> <crc_lo> <crc_hi>
```
Например при 50.00 Гц данные = `13 88` (0x1388 = 5000), полный ответ `01 03 02 13 88 B5 12` — *computed*, не зашивать в golden-тест до верификации.

## Гипотеза (unverified) — НЕ использовать как golden без проверки

### 5. Попытка записи в регистр только для чтения (0x06 в 0x3000)
Предполагаемый запрос (*computed*, поведение прибора неизвестно):
```text
01 06 30 00 00 00 F1 94
```
Предполагаемый exception-ответ (стандартный Illegal Data Address; код `0x02` — placeholder):
```text
01 86 02 C3 A1
```
В присланном фрагменте руководства этот обмен отсутствует. Код исключения для «read-only» (руководство упоминает детальный код 0x11) не раскрыт. **TODO on bench:** подтвердить, отвечает ли привод 0x02, 0x03 или иначе, и как передаётся детальный код 0x11.

## 7. Пример расчёта CRC (для автотестов)
Вход (адрес+функция+данные): `01 03 30 00 00 01` → CRC-16/MODBUS = `0x0A8B` → передача `8B 0A`. Совпадает с примером 4 — это опорный вектор для unit-теста CRC.
