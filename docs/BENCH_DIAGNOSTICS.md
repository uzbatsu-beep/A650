# Стендовая диагностика A650 / A650M (экспериментально)

Сценарий для Windows 10 x64 с USB–RS-485 и отдельным ПЧ с двигателем.
Это **исследовательский CLI**, а не проверенный аппаратный релиз или GUI-функция.
Перед первым запуском убедитесь в безопасности стенда и правильных настройках F15.

Установите Python и зависимости проекта с serial extras, затем выполните:

```powershell
python -m a650.diagnostics --port COM3 --model A650 --slave 1 --baud 9600 --parity N --stopbits 1 --output bench-stop.jsonl
```

Параметры `--parity` и `--stopbits` сверить с дисплеем ПЧ:
в руководстве противоречие между 8N1 и 8N2. Для второго снимка после
**ручного** запуска двигателя используйте новое имя файла
(`bench-run.jsonl`). Вывод JSONL содержит UTC-время, код, адрес, raw
и quality/error. Сохранение без перезаписи; перед публикацией удалите
чувствительные сведения о стенде.

Опрос включает документированные F/U RAM-адреса из исследовательского
каталога, исключает конфликтные/дублирующиеся адреса и пароль F00.00,
не опрашивает неподтверждённую H-группу. Каждый запрос — FC03, 1 регистр,
без записи и без автоматических повторов. Часть адресов может быть
недоступна на конкретной модели или прошивке; ошибки сохраняются в отчёте.
Неизвестные масштабы и signedness намеренно **не интерпретируются**.
Сканирование сотен параметров может занять несколько минут.

**Ограничение:** эта первая реализация не включает UI с enum/числовыми
редакторами и не создаёт Windows ZIP. Для выпуска готового релиза
необходимо интегрировать GUI, проверить CI, собрать Windows и провести
приёмку на стенде. Никакой автоматической записи в ПЧ нет.
