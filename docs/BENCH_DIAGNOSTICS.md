# ONI A650/A650M — диагностика доступности Modbus-регистров

## Назначение и ограничения

Модуль создаёт **эмпирическую карту чтения конкретного экземпляра ПЧ**.
Каждый адрес запрашивается отдельно: Modbus RTU FC03, Count=1.
Успешный ответ доказывает читаемость адреса на этом экземпляре при данных
условиях, **но не доказывает** правильность назначения, масштаба, типа данных,
RW-доступа или применимость к другим версиям прошивки.

Основание: реальный стендовый тест 16.11.2026, COM3 / 9600 / 8N1 / Slave 1:
- FC03 Count=1: успешные ответы 0x3000, 0x2001–0x2004, 0x2100–0x2103;
- FC03 Count=1: исключение 0x02 на 0x2000 и 0x2005;
- FC03 Count=4: исключение 0x03 на диапазоне 0x2100–0x2103.
Проверка на одном ПЧ не является универсальной спецификацией.

## Безопасность

1. Работа только в режиме **«только чтение»**; разрешение записи выключено.
2. Обычный циклический мониторинг приостанавливается на время обследования.
3. Используется **только заранее сформированный список уникальных F/U RAM адресов**
   без конфликтных/дублирующихся записей каталога; дополнительно:
   0x2001 и 0x2100–0x2103.
4. Исключаются F00.00 (пароль), H-группы с неизвестной адресацией,
   EEPROM-зеркала и 0x2000/0x2005 (банк управления с подтверждёнными
   исключениями чтения). Запись функций FC06/FC16 и управление запрещены.
5. Автоматического опроса всех 65 536 адресов **нет**. Не выполнять
   произвольное сканирование неизвестных областей без анализа руководства
   и отдельной процедуры безопасности.
6. Один запрос одновременно, без повторов при тайм-ауте; пауза 100 мс
   между запросами по умолчанию. Остановка действует между запросами.
7. Перед испытанием обеспечить безопасное состояние двигателя/нагрузки,
   правильный интерфейс и возможность физического останова.

## GUI (Windows 10 x64, предварительная версия)

1. Открыть «Подключение и мониторинг», задать COM-порт, F15, адрес ПЧ.
2. НЕ устанавливать флаг «Разрешить запись и управление».
3. Подключиться. Конфигуратор проверит связь чтением 0x3000.
4. Проверить модель A650/A650M во вкладке «Каталог параметров».
5. Вернуться в мониторинг и нажать «Сканировать каталог…».
6. Выбрать **новый** файл .jsonl; подтвердить длительное чтение.
7. Наблюдать прогресс; «Остановить» корректно завершает текущий запрос.
8. Для продолжения выбрать «Продолжить скан…» и сохранённый .jsonl
   **на той же модели, slave ID и неизменном списке регистров**.
9. На завершении рядом с JSONL создаётся CSV (UTF-8 с BOM для Excel).

Во время сканирования ручное чтение через инспектор отключается;
Live status снова запускается после завершения или отмены диагностики.
Если включена запись, GUI не позволит запустить скан — переподключитесь
в режиме read-only.

## CLI (Python + pyserial)

```powershell
python -m a650.diagnostics --port COM3 --model A650 --slave 1 --baud 9600 --parity N --stopbits 1 --timeout 0.8 --delay-ms 100 --output a650-bench.jsonl
```

Продолжение после остановки/отключения:

```powershell
python -m a650.diagnostics --port COM3 --model A650 --slave 1 --baud 9600 --parity N --stopbits 1 --output a650-bench.jsonl --resume
```

Используйте новое имя файла для работающего двигателя или другой прошивки.
При изменении модели / списка регистров / slave scanner отклонит resume.

## Формат и интерпретация

JSONL — основная запись: заголовок `type=session` с моделью, slave,
контрольной суммой списка и количеством адресов, затем по одной строке
`type=reading` на регистр. Поля: `timestamp` UTC, `code`,
`address` (hex), `function=3`, `count=1`, `request_hex`
(ожидаемый TX-кадр), `elapsed_ms`, `quality`, `raw` либо `error`.

`quality`: `ok`, `exception_0x02`, `exception_0x03`,
`timeout`, `crc_error`, `error`. **Фактические RX HEX-кадры в этом
PR пока не регистрируются** — для этого потребуется отдельный перехват
на уровне транспорта без раскрытия чувствительных данных.

Отчёт создаётся инкрементально с flush после каждой строки.
CSV восстанавливается по JSONL при завершении или штатной отмене.
После аварийного завершения последний повреждённый JSONL-фрагмент
не допускается к автоматическому resume: сначала сохраните копию,
проверьте и восстановите файл вручную.

Перед передачей диагностических файлов третьим лицам удалите
пароли, уникальные идентификаторы оборудования и другую чувствительную
информацию. В репозиторий результаты с реального стенда не коммитить.

## Готовность к релизу

Наличие исходников и PR **не равно** проверенному релизу.
Перед Windows ZIP необходимы полный pytest, compile-check, GUI smoke-test
и повторное испытание на реальном ПЧ. **Запись и управление остаются
вне рамок этой диагностической процедуры.**
