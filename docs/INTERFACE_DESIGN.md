# Дизайн конфигуратора ONI A650

Рабочая спецификация · 15 ноября 2026 · версия 0.1 для обсуждения

## 1. Назначение и честный статус

**Текущая сборка — технический прототип, не завершённая альфа конфигуратора.**
После первоначальной оценки добавлены типизированные редакторы для 14 полей,
офлайн-проекты, история, сравнение и экспериментальный предпросмотр ODS.
Фактическое покрытие и ограничения описаны в
[DEVELOPMENT_STATUS.md](DEVELOPMENT_STATUS.md). Полная аппаратная резервная
копия, применение параметров и Windows-приёмка ещё не реализованы/не завершены.
Запуск симулятора и автотесты не означают готовности UX или реального ПЧ.

Этот документ описывает **целевой интерфейс**, а не уже реализованные функции.
Заказчик подтвердил: главный экран — настройка и сравнение параметров;
редактирование — в таблице, подробности — справа. Windows, русский язык,
A650/A650M, USB–RS-485 и офлайн-симулятор — текущий объём. Совместимость
с конкретным ПЧ и Windows-сборкой проверяется отдельно.

### Сценарии первого релиза

1. Офлайн: создать проект, выбрать модель, найти F15.01, увидеть варианты и
   выбрать «Чётная, 8E1», сохранить проект, позже открыть его и увидеть выбор.
2. Подключение: выбрать COM, явно задать формат и адрес, проверить связь
   чтением; видеть модель как выбранную пользователем, если она не установлена
   автоматически. Никакие данные не записываются при подключении.
3. Сравнение: прочитать значения с ПЧ, увидеть текущие, проектные и отличия;
   подготовить набор и только после проверки и подтверждения применить.
4. Диагностика: понять, какие данные актуальны, почему строка недоступна,
   и что произошло, если ответ на запись потерян.

## 3. Экран параметров: рабочая компоновка

Ориентир для 1440×900, 100 % масштаба. На 1366×768 при 125 % интерфейс
адаптируется: панель справа сворачивается, вертикальная прокрутка независима;
при 200 % нет перекрытия команд, горизонтальная прокрутка таблицы допустима.

```text
┌ ONI A650     Проект: Насосная-1                 Симулятор ●   Только чтение ┐
│ Параметры    Мониторинг    Диагностика    Журнал        Подключение / COM3   │
├──────────────────────────────────────────────────────────────────────────────┤
│ ПАРАМЕТРЫ                                      [Считать] [Сравнить] [Применить 2] │
│ Модель A650 ▾   Поиск кода / названия…     [Все ▾] [Изменённые] [Ошибки]   │
├────────────────┬───────────────────────────────────────┬─────────────────────┤
│ Группы         │ Код    Параметр    ПЧ       Проект     │ F15.01 Формат связи │
│ F00 Системные  │ F15.00 Скорость    9600     9600      │                     │
│ F01 Частота    │ F15.01 Формат      Нет 8N2  [Чётн. 8E1 ▾] ●│ Описание        │
│ …              │ F15.02 Адрес       1        1          │ Диапазон и варианты │
│ F15 Связь  •1  │ F18.08 R статора  —        —      ⚠   │ Доступ и состояние  │
│ H00 Насосы     │                                        │ Адреса / источник  │
├────────────────┴───────────────────────────────────────┴─────────────────────┤
│ ● 1 изменение   ⚠ 1 конфликт   Последнее чтение: 12:45:06    [Журнал ▴]    │
└──────────────────────────────────────────────────────────────────────────────┘
```

Данные на рисунке — **иллюстрация**, не показания и не проверенный проект.
Строка выделяется для просмотра; выбор другой строки обновляет правую карточку
даже после фильтрации и прокрутки. Кнопка применения показывает число только
прошедших проверку изменений. В offline она недоступна с объяснением;
редактирование проекта при этом работает. Панель подключения открывается
отдельно и не вытесняет основную таблицу. Состояние устройства и подключения
всегда видно, действия «Пуск/Стоп» — отдельная область, не рядом с ячейкой
редактора. Программный останов не заменяет аппаратный аварийный останов.

### Таблица

- Колонки: отметка, код, название, значение ПЧ, проектное значение,
  единица, состояние. Адреса/тип/источник — в карточке и по выбору колонок.
- Группы, поиск по коду/русскому названию, фильтры «все», «изменены»,
  «нужна проверка», «только чтение»; сортировка не сбрасывает значения и
  выбор. Состояние отображается текстом/значком и цветом, не одним цветом.
- Строки: «не прочитано», «совпадает», «изменено в проекте», «недоступно»,
  «конфликт источников», «ошибка валидации», «запись…», «проверено» и
  «результат неизвестен». Значения «0», пустое, не прочитано и ошибка связи
  различаются. Нельзя подставлять default вместо непрочитанного значения.
- Детали: полное название и описание, значение ПЧ/проекта, допустимые
  варианты, доступ/ограничения, диапазон и единицы, RAM/EEPROM, происхождение
  каждого спорного поля (PDF/EXE, редакция, страница), статус проверки и
  причина блокировки. Инженерные метаданные сворачиваются; они не занимают
  главную часть карточки и не заменяют редактирование.

## 4. Типизированные редакторы — обязательное требование

| Тип | В таблице | Валидация и отображение |
|---|---|---|
| Enum / перечисление | `QComboBox` со строками «код — название» | Храним числовой код отдельно от переведённой подписи; только известные варианты. Не показываем спиннер. |
| Число | Числовое поле | Точное десятичное значение, единица рядом, границы/шаг/масштаб из проверенных метаданных; без округления вне допустимого шага. |
| Логический | Флажок или список двух именованных состояний | Использовать только если кодирование действительно бинарное и описано. |
| Bitfield | Кнопка «Настроить…» и сводка | Именованные биты; незнакомые биты сохраняются, при неполном кодеке запись запрещена. |
| Десятичные разряды | Составной редактор разрядов | Не путать с битами. В каждой позиции свои варианты; незнакомые позиции сохраняются или запись блокируется. |
| Только чтение | Текст, единица, время чтения | Нет активного редактора и нет включения в запись. |
| Пароль / секрет | Маскированный специализированный ввод | Без экспорта значения в журнал, отчёт или скриншот; запись только при подтверждённой политике. |
| Тип/варианты/масштаб неизвестны или конфликтуют | Неактивное поле с причиной | Допускать просмотр и пометку данных, не предлагать случайный числовой редактор или запись. |

### Конкретный enum-пример F15.01

По руководству издания 3, стр. 133 (для профиля, где эти сведения
подтверждены):

| Сохранённый код | Подпись в списке |
|---:|---|
| 0 | Нет чётности · 8N2 |
| 1 | Чётная · 8E1 |
| 2 | Нечётная · 8O1 |
| 3 | Нет чётности · 8N1 |

При получении кода 9 показывать «Неизвестное значение (9)», сохранять исходное
число и не выбирать автоматически 0. Пока пользователь не выбрал допустимый
вариант, изменение не считается готовым к записи. Если EXE и PDF расходятся
(для 8E1 есть расхождение в тексте EXE), показать предупреждение и ссылку на
источники; конфликт нельзя тихо исправлять или разрешать запись на его основе.
F15.01 меняет связь: для фактического применения нужен отдельный сценарий
подтверждения и переподключения; выбор в офлайн-проекте не меняет COM-порт.

### Конкретный числовой пример F13.01

По насосному руководству стр. 19 — отображаемый диапазон 0,0–100,0 %, шаг
отображения 0,1 %. Вводить `50,0` или `50.0` согласно локали, хранить как
Decimal; метаданные физического кодирования пока не подтверждены, поэтому такой
офлайн-ввод не даёт права отправить слово Modbus. Символ `×` и `△` из
руководства сохранять отдельно как условие изменения, а не тип редактора.

### Клавиатура и доступность

Tab/Shift+Tab — между областями; стрелки — по таблице; Enter/F2 — открыть
редактор; Escape — отменить незавершённый ввод; Enter — подтвердить локальное
изменение, не отправляя в ПЧ. В combo стрелки меняют подсветку, Enter выбирает,
Escape закрывает без изменения. Фокус видим в светлой/тёмной темах и при
масштабировании; проверять Windows Narrator, контраст и управление только
клавиатурой. Не назначать одиночную клавишу команде движения.

## 5. Модель данных и происхождение

Сейчас `CatalogEntry` содержит `name`, диапазон и адреса, но **не содержит**
выверенные `editor_kind`, enum-значения, точный codec, единицы, signedness и
атрибут доступа. Поля `type_raw`/`attribute_raw` извлечения EXE непрозрачны;
по ним нельзя угадывать редактор. Отдельно извлечь enum-записи и сверить с PDF
и моделью; учесть, что примеры F15.01 в EXE и PDF противоречат друг другу.

Предлагаемая модель одного параметра:

```text
identity: {model, profile_revision, code, stable_id}
label, description, unit, precision, display_range, editable_when
editor: {kind, options: [{code, label, availability, source}], allow_unknown: false}
wire: {ram, eeprom, signedness, scale_decimal, codec, verified}
provenance: {field -> [{document, edition, page, evidence, confidence}]}
conflicts: [{field, alternatives, status}]
value: {device_raw?, device_engineering?, observed_at?, quality,
        project?, default?, dirty, validation, write_outcome}
```

`?` означает отсутствие подтверждённых данных, не ноль. `stable_id` должен
различать дубли F17.28; ключом только `code` пользоваться нельзя. Несколько
профилей модели или ревизии не объединяются по имени. Каталог отображается
и работает в установленном пакете; схема версионируется и валидируется.

## 6. Запись и контроль состояния

1. Локальное редактирование без подключения не включает запись. Показать
   статус проекта, количество изменений и сохранение в файл проекта.
2. Перед физическим применением: явно разрешённый режим, подтверждённые
   модель/адрес/codec и допустимость по состоянию; прочитать текущие значения,
   сформировать резервный снимок и показать diff «ПЧ → проект» с единицами.
   Конфликт адреса, дубли, неизвестный масштаб или неподтверждённый статус
   блокируют соответствующую запись. Параметры связи и критичные группы —
   отдельные сценарии подтверждения.
3. Перечислить только проверенные изменения и целевую память RAM/EEPROM,
   показать количество и потенциальное влияние. Оператор подтверждает
   конкретный список; запись идёт по одному FC06, без автоматического повтора.
   Серия FC06 не является атомарной транзакцией, «откат» не обещается.
4. После каждой операции показать результат и по возможности перечитать.
   Тайм-аут, повреждённый или несоответствующий ответ после отправки означает
   «неизвестно, могло выполниться»: остановить очередь, не повторять и
   предложить безопасную проверку. Для неподтверждаемой команды управления
   не представлять отсутствие эха как доказательство отсутствия движения.
5. В журнале: время, источник операции, адрес/параметр, подтверждение,
   результат/ошибка, идентификатор сеанса. Секреты не записывать; ошибка
   ведения обязательного аудита должна быть явно обработана до отправки.

Симулятор явно обозначается на всех экранах и не создаёт видимости проверки
реального устройства. Потеря связи не превращает последнее значение в 0;
отметить его устаревшим и показать время наблюдения.

## 7. Критерии приёмки и очередь реализации

**Этап A — интерактивная альфа без записи в ПЧ.** Модель параметра и enum,
редактирование в ячейке, поиск/группы, локальный проект, сравнение Set/Read,
симулятор, конфликты и русские тексты. Демонстрация F15.01: 4 именованных
варианта, сохранение кода, неизвестный код, отмена и восстановление проекта.
Демонстрация F13.01: 50,0 %, ошибка диапазона и корректная точность. Дубликат
F17.28 и конфликт F18.08 видны и не теряются при поиске. Никаких команд на ПЧ
через этот редактор. Отключить существующие неподтверждённые элементы
управления физическим приводом в демонстрационном режиме, отдельно от симулятора.

**Этап B — надёжное чтение.** Windows/COM, один запрос на канал, ограничения
до 8 регистров, тайм-аут, фрагментация, поздний ответ, отключение, stale,
автоматизированные тесты подставного порта. Точная модель остаётся явно
выбранной, пока идентификация не реализована и не проверена.

**Этап C — контролируемая запись.** Отдельные разрешения для параметров и
движения, корректные кодеки и доступы, diff, аудит, проверка подтверждения,
восстановление после неизвестного исхода. Сначала симулятор, затем изолированный
стенд с известной моделью и прошивкой.

**Этап D — диагностика и отчёты.** Ошибки с привязкой к проверенной редакции,
история и снимки, экспорт без секретов; мониторинг и графики после оценки
пропускной способности. Мастера и новые модели — отдельно после сверки.

Для A: тесты модели и Qt-delegate (enum код↔подпись, unknown, конфликт,
десятичные разряды, границы, Escape, dirty/undo, персистентность), GUI-сценарий
на симуляторе и проверка Windows .exe; пользователь оценивает реальный сценарий
редактирования, а не только скриншот. Для B/C добавляются тесты транспорта,
имитация потери ответа и протокол стендовой проверки. Целевые показатели времени
отклика и полной загрузки измеряются после замера на выбранном оборудовании;
значения 10–50 мс / 4,5 с из приложенного ТЗ не считаются доказанными.

## 8. Что нужно уточнить позже

- Фактическая модель/прошивка и рабочий режим ПЧ — до стендовой записи.
- Реальный `.ods` OniDriveStudio — для проверки совместимости импорта/экспорта;
  пока наш читатель проверен синтетическими данными.
- Приоритеты последующих экранов (графики, ошибки, пусконаладка) можно
  согласовать после оценки этапа A. Переписывание на другой стек и публикация
  новой версии не входят в этот дизайн-документ.
