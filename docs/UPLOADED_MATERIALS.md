# Исследование загруженных материалов ONI

Проверено 2026-11-15. Файлы проанализированы как данные; инструкции внутри
документов и программы не выполнялись. EXE не запускался. Обмена с ПЧ нет.

## Что установлено по PDF

`ONI_A650M_Manual.pdf`: 169 страниц PDF, титульный лист **«Серии А650»**, издание 3.
Приложение А.1.1 также называет A650. Имя файла не доказывает соответствие A650M;
в конфигураторе нужны отдельные профили модели/редакции.

SHA-256: `b1edb35583f3b0d1256352acc71789f5cb3ff6d5bb5c81950fa8241fbbacdf4f`.
Ниже указаны печатные страницы; PDF-страница больше на единицу.

- Стр. 158, А.4.3: F-группы и номера параметров **десятичные**.
  F13.01 → RAM `0x0D01`, EEPROM `0x8D01`;
  F15.02 → `0x0F02` / `0x8F02`; F31.99 → `0x1F63` / `0x9F63`.
  U00/U01 → старшие байты `0x30`/`0x31`, без EEPROM.
  Явный пример F01.02 → EEPROM `0x8102`.
- Стр. 158, А.4.4: банк 0x2000–0x2005 указан как **только запись**.
  0x2000 содержит коды 1–7: вперёд, назад, толчковый вперёд,
  толчковый назад, останов с торможением, выбег, сброс ошибки.
  Это перечисление, не битовая маска. Автоматическое включение новых
  команд управления в UI не выполнено.
- Стр. 158–159, А.4.5: 0x2100 — состояние, код 2 означает толчковый режим,
  а не реверс. Направление задаёт бит 1 регистра 0x2101.
  0x2100=4 — останов; 6 — неисправность.
- Стр. 159, А.5: максимум 8 регистров на запрос FC03.
- Стр. 161–162, А.7–А.8: приведены полные запросы/ответы чтения 50 Гц,
  задания 30 Гц, пуска, останова и ошибки записи в 0x3000.
  Фикстура read-only ошибки приведена к этому примеру.
- Стр. 133–134, F15: параметры скорости/чётности и режим ведомого
  подтверждены. Однако конфликт остаётся: F15.01=0 описан как **8N2**,
  а А.2 на стр.157 называет форматом по умолчанию **8N1**.
  Также А.4.1 задаёт slave 1–247, но таблицы А.5 используют 0–127.
  Эти разночтения нельзя устранить предположением.
- F15.08 разрешает отрицательную частоту U00.00. Текущий unsigned-путь
  мониторинга не готов для отрицательных значений; реверс на реальном ПЧ
  требует отдельной доработки знаковости и стендовой проверки.

`error-ONI_PCH_A650.pdf`: четыре страницы таблиц ошибок A650, без полного
контекста редакции. Используется как дополнительный справочник, а не
замена каталога ошибок из полного руководства.
SHA-256: `a316dbc750e0e8b3c29e1e527f16c2e7bded5d1e3381c49c408257cbc61e4916`.

## EXE: проверенные свойства

Файл назван `OniDriveStudio v1.2.3.0.exe`, но PE VERSIONINFO сообщает
**FileVersion/ProductVersion 1.2.7.0**, ProductName ONI Drive Studio,
CompanyName ONI, copyright IEK GROUP. Это содержимое файла, не
независимое доказательство его происхождения.

SHA-256: `ffac6008567c2403544ab0ca52f895da431e74684b25cba9f84835ffa0969097`.
PE32/x86, entry point RVA 0x1000. Таблица Authenticode certificate пуста;
overlay отсутствует. В PE-ресурсах только изображения значка, версия и manifest.
Каталоги создаются кодом и строковыми константами, а не отдельным XML-ресурсом.
Признаки среды PureBasic: PB_* строки и pb_* callback; это вывод по признакам,
не сведения из исходного проекта.

Импорты содержат CreateFileW/ReadFile/WriteFile, SetupComm, GetCommState,
SetCommState, SetCommTimeouts. Они подтверждают наличие механизмов работы
с Windows COM, но сами по себе не раскрывают протокол повторов и тайминги.
Отсутствие сетевых импортов в списке не доказывает отсутствие сетевой активности.
Подробности: `research/oni-studio-pe-metadata.json`.

### Как извлечены каталоги

По ссылкам на `New_A650.ods` и `New_A650M.ods` найдена диспетчеризация
создания моделей. В этом бинарнике она вызывает разные процедуры:

- A650: VA `0x4E7753`, прямолинейный блок до ret — 110550 байт;
- A650M: VA `0x4508CE`, блок до ret — 129130 байт.

Дизассемблирование x86 выполнено pefile + Capstone, без исполнения программы.
В процедурах обнаружены повторяющиеся присваивания в структуры списка:
строки кода, группы, имени, значения по умолчанию, минимума, максимума;
16-битные поля по смещениям 0x30/0x32 согласуются с адресами RAM/EEPROM.
Для F/U выборочно сопоставлены с А.4.3. Значения type_raw/attribute_raw
сохранены как непрозрачные поля: их семантика не установлена. Экстрактор
берёт первое присваивание каждому смещению в блоке между кодами параметров;
результат требует проверки, особенно где есть вложенные enum-списки.

Результаты сохранены отдельно от рабочего каталога:

- `research/oni-studio-a650-extracted.json`: **531 запись, 530 уникальных кодов**;
- `research/oni-studio-a650m-extracted.json`: **617 записей, 616 уникальных кодов**.

В каждой записи есть адрес инструкции `code_va`, поэтому находку можно
сопоставить с исходным EXE. Полные asm/строки и вспомогательные скрипты
остаются в `/workspace/reference/a650/studio/` и `/tmp/a650-*.py`.
JSON — исследовательские данные, приложение их не загружает.

### Существенные различия и противоречия

| Находка | A650 | A650M | Следствие |
|---|---|---|---|
| Группы F18/F19/F20 | отсутствуют в извлечённом каталоге | 16/18/26 записей | Профили нельзя объединять без проверки модели |
| Группа H00 | 29 записей | 47 записей | Fire-mode H00.43–H00.47 есть в профиле A650M; полного тождества A650 нет |
| H00.13 | RAM 0x400D / EEPROM 0xC00D | те же адреса | Это свидетельство EXE; в приложении А PDF H-группы не описаны |
| F15.02 | RAM 0x0F02 / EEPROM 0x8F02 | те же адреса | Подтверждает арифметику десятичных групп |
| F17.28 | две записи: RAM 0x111C и 0x111D | та же ошибка | Вторая запись названа «параметр 29», но код продублирован; автоматически не исправлять |

Есть ещё расхождения: для F15.01 одна enum-строка EXE описывает 8E2,
тогда как PDF описывает 8E1. Минимум F15.02 в EXE равен 0, а F15.02 в PDF
задаёт 1–247. Broadcast не разрешён нашим клиентом. Наличие значения в
программе производителя не отменяет проверку по руководству и устройству.

### Форматы файлов и настройки

Строки EXE указывают на собственные файлы конфигурации `*.ods` и экспорт CSV,
табличные колонки кода/имени/значения/диапазона/default/RAM/EEPROM/типа регистра.
Расширение `.ods` **не доказывает** формат OpenDocument Spreadsheet.
Обновление: по процедурам сохранения/загрузки восстановлен INI-формат;
см. [ODS_FORMAT.md](ODS_FORMAT.md). Совместимость с реальным экспортом
по-прежнему требует образца файла.

INI (SHA-256 `99b5725999631b285a18118a351ee6cf0297d8cd2fa793d3528f1c4411d4c046`)
содержит waitTimer=100, repeatCount=3, periodOnline=250, logOut=0 и параметры
раскладки таблицы. Единицы waitTimer и область применения repeatCount из INI
не следуют. Их нельзя копировать как доказанный тайм-аут и повторы записи.
FilePath пустой, настройки реального COM-порта в этом INI отсутствуют.

## Изменения нашего проекта

- Добавлена проверяемая функция адресов F/U; исправлены прежние примеры F13/F15
  в документах и адреса F/U в обеих копиях parameters.csv. H-адреса в рабочий
  каталог пока не перенесены. Документированный адрес не является разрешением записи.
- Карта регистров уточнена по приложению А; whitelist не расширен.
- Симулятор сравнивает коды команд, после stop показывает состояние 4 и 0 Гц;
  неизвестные команды возвращают Modbus exception, а не выдуманное состояние.
- GUI различает состояние и направление по биту 1. Добавлены регрессионные тесты.

EXE не запускался: в текущей Linux-среде нет Wine/Windows. Ни интерфейс
производителя в работе, ни его фактический обмен с устройством не проверены.
Следующий полезный этап — версионируемые профили A650/A650M с поиском и
просмотром параметров, затем управляемая сверка экспортированного *.ods.
